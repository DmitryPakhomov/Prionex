## Окружение

- Windows, Node.js v24.14.1, npm 11.11.0.
- Стенд запущен на Windows через Docker Desktop (Docker Engine CLI 29.9.2) и Docker Compose v5.6.1. UI доступен на 4200, API на 8091, MariaDB на 3306.
- Выбран `SPRINT=sprint5-with-bugs`. Зафиксированный коммит Toolshop — [`ae7caecb811dd8952c09d997e69be7cb946ecd44`](https://github.com/testsmith-io/practice-software-testing/commit/ae7caecb811dd8952c09d997e69be7cb946ecd44). Запуск из исходников через Docker Compose.
- Исходники приложения хранятся в отдельном клоне `.toolshop/`, который исключён из Git.

## Локальный запуск

После установки WSL2 и запуска Docker Desktop проверьте `docker version` и `docker compose version`. Выполните команды из корня QA-репозитория. Если `.toolshop/` уже скачан, пропустите `git clone`.

```powershell
$toolshopRef = 'ae7caecb811dd8952c09d997e69be7cb946ecd44'
$toolshopSprint = 'sprint5-with-bugs'

git clone https://github.com/testsmith-io/practice-software-testing.git .toolshop
Set-Location .toolshop
git checkout --detach $toolshopRef
git rev-parse HEAD
Set-Content -Path .env -Value "SPRINT=$toolshopSprint" -Encoding ascii
docker compose -f docker-compose.yml -f docker-compose.override.yml -f ../app-changes/compose.sprint5-with-bugs.yml up -d
docker compose ps
```

Переопределение из `app-changes/` пропускает вызов `set-version.js`: на выбранном коммите файл есть в `sprint5`, а Compose вызывает его и в `sprint5-with-bugs`. Перед первым заполнением базы дождитесь готовности MariaDB и успешного завершения сервиса `composer` (статус `Exited (0)` в `docker compose ps -a`).

```powershell
docker compose exec laravel-api php artisan migrate --seed
```

Проверьте каталог на <http://localhost:4200> и Swagger на <http://localhost:8091/api/documentation>. Демо-аккаунты берите из README выбранной версии. Для автотестов планируются отдельные пользователи и корзины.

Для ручных сценариев после seed доступны покупатели `customer@practicesoftwaretesting.com` и `customer2@practicesoftwaretesting.com`. Демо-пароль указан в README Toolshop. Негативные проверки входа выполняем с отдельными тестовыми аккаунтами, чтобы не заблокировать общие.

Если сборка из исходников не работает, проверьте, соответствует ли образ из `docker-compose.prod.yml` заданному коммиту и спринту. При подтверждённом соответствии можно применить `docker compose -f docker-compose.prod.yml up --pull missing -d`. При работе с этим вариантом передавайте тот же `-f` командам `ps` и `exec`.

Источник команд — [инструкция Toolshop на выбранном коммите](https://github.com/testsmith-io/practice-software-testing/blob/ae7caecb811dd8952c09d997e69be7cb946ecd44/docs/getting-started.md).

## Автотесты

Из корня QA-репозитория при работающем локальном стенде выполните:

```powershell
npm ci
npx playwright install chromium
npm test
npx playwright show-report reports/html
```

Playwright использует локальные адреса из `.env.example` по умолчанию. Чтобы изменить порты, скопируйте файл в `.env` и задайте адреса своего локального стенда. Каждый UI-тест получает чистый браузерный контекст. Для оформления создаётся отдельный покупатель с уникальным email и случайным паролем через локальный API. Тесты каталога используют данные seed. База во время прогона не сбрасывается.

Последний прогон — 6 прошли, 7 ожидаемо упали. Теги `@BUG-001`–`@BUG-007` связывают падения с дефектами. Команда возвращает ненулевой код, чтобы регрессии оставались видны. Для прогона отдельного кейса используйте `npm test -- --grep CART-01`. Этот запуск также перезаписывает отчёт, поэтому для итогового отчёта выполните полный `npm test`.

[HTML-отчёт](reports/html/index.html) с trace и скриншотами и [текстовые контексты падений](reports/results/) сформированы по текущему коду. Автотесты написаны для задания. Селекторы и маршруты сверены с закреплёнными исходниками Toolshop, внешний тестовый код не заимствован.
